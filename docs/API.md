# Zenivo API reference

Zenivo serves a REST API, one WebSocket and two long-lived HTTP streams from the same port as the
web UI. This page lists every endpoint with its purpose and key parameters. It is generated by
reading `src/api/routes.py`, `src/api/main.py` and `src/api/stream.py`; response bodies are not
described here. When the service runs, FastAPI also publishes the live schema at `/docs`
(Swagger UI) and `/openapi.json`.

- Base URL: `http://<host>:<port>` (default port 8080).
- Format: JSON unless noted. Request bodies for `POST`/`PUT` are JSON.
- **What leaves the station**: see [TRANSPARENCY.md](TRANSPARENCY.md) for every outbound connection behind these endpoints.
- **Authentication**: one admin, session cookie `zenivo_session`, see [Authentication](#authentication) and [SECURITY.md](SECURITY.md). Routes marked **admin** in the tables below answer `401 {"detail":"Sign in as admin","code":"auth"}` to guests; every `POST`/`PUT`/`DELETE` is admin unless stated.
- Times: epoch parameters are Unix seconds. Recorded timestamps are local ISO 8601 with offset.
- Validation errors return HTTP 422. Names such as `/api/allsky/ingest/*` and `/uploads/allsky/...`
  keep the original "allsky" name.

## Authentication

Default deny: any request that is not `GET`/`HEAD`/`OPTIONS` needs an admin session, except the open routes below.
Admin-only reads: `/api/logs`, `/api/logs/download`, `/api/community/settings`, `/api/focus`, `/api/focus/frame`,
`/api/focus/overview.jpg`, `/api/storage`, `/api/camera/devices`, `/docs`, `/redoc`, `/openapi.json`. Admin pages: `/settings`,
`/calibration`, `/focus`, `/logs`, `/obs/dock` (guests are redirected to `/login?next=<path>`). A state-changing request with an
`Origin` header that differs from `Host` gets 403.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/auth/status` | `{configured, admin, setup_pending}` |
| POST | `/api/auth/setup` | Body `{code, password}`. First start only: the code is in `data/admin_setup_code.txt`. Sets the password and signs in. 403 wrong code, 409 already set, 422 bad password, 429 throttled |
| POST | `/api/auth/login` | Body `{password}`. Sets the session cookie. 403 wrong password, 409 not set up, 429 throttled (`Retry-After`) |
| POST | `/api/auth/logout` | Ends this session |
| POST | `/api/auth/password` | **admin**. Body `{current, new}`. Ends every other session |
| POST | `/api/auth/logout-all` | **admin**. Ends every session |

Guests get the station location rounded to `public_precision_deg` (`"location_rounded": true`) in
`/api/station/config`, `/api/status`, `/api/telemetry`, SSE/WebSocket telemetry, the plate-solve status and the `station`
object of `/api/adsb/aircraft` and `/api/satellites`; the ADS-B receiver address and Flightradar24 e-mail are blank.

## WebSocket `/ws/live`

Connect to `ws://<host>:<port>/ws/live?binary=1`. Without `binary=1` the endpoint speaks legacy JSON.

**Binary mode** (used by the UI):

- Server to client, **ASB1** packets: a 92-byte little-endian header (exposure, gain, fps, star
  count, cloud %, temperature, sensor registers, histogram statistics, calibration state), then four
  256-entry `uint32` histograms (R, G, B, Y), then the JPEG. The push period is
  `clamp(0.95 x exposure, 0.35, 2)` seconds.
- Client to server, **ASC1** packets: command `1` sets the mode (auto or manual), command `2` sets
  exposure and gain.
- A text message `{"type": "ae_lock", ...}` is sent when the lock state or the frame brightness changes.
- Broadcast text messages: `{"type": "obs_overlay", ...}` and `{"type": "obs_reload"}`.

Commands that change state (ASC1 `1` and `2`, `set_exposure`, `set_gain`, `set_mode`, `trigger_master_dark`) need the admin session cookie on the handshake and a matching `Origin`; for guests the server answers `{"type":"error","code":"auth","message":"Sign in as admin"}` and does nothing.

**JSON mode** (tests and simple clients): send `{"action": ...}` with one of `ping`,
`get_telemetry`, `get_status`, `set_exposure` (`exposure_s`, `gain_db`), `set_gain` (`gain_db`),
`set_mode` (`mode`) or `trigger_master_dark` (`num_frames`, `exposure_s`, `gain_db`). The server
answers with a message whose `type` is `pong`, `telemetry`, `status`, `exposure_result`,
`gain_result`, `mode_result` or `master_dark_result`, and `ack` for an unknown action.

## Server-sent events

`GET /api/stream/sse` (alias `/api/sse`) sends telemetry as `text/event-stream` every `interval`
seconds. Behind nginx, disable buffering (see [INSTALL.md](INSTALL.md#nginx-reverse-proxy)).

## Sync API (optional ingestion server)

Zenivo itself is the client of these endpoints; it does not serve them. Each push round, the sync
worker sends:

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/allsky/ingest/frame` | Multipart `image`, headers `X-Exposure-Sec` and `X-Gain-Db` |
| POST | `/api/allsky/ingest/telemetry` | Telemetry JSON |

The client identifies itself with the header `X-Device-Id: zenivo-<hostname>` (override with `ZENIVO_DEVICE_ID`).
