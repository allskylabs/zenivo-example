Detection

Meteor, aircraft, satellite, flash and cloud detection, and the cloud cover analysis.

Event detection

Streaks and flashes are looked for at night only (sun below −8°), on a 640 px gray copy of each new frame compared with the previous one: a few ms per frame. A streak in a single frame is a meteor; a dashed one or one that continues along the same line in the next frame is an aircraft (faint and steady: a satellite). Cloud changes reuse the cloud cover samples, so they need “Star count & cloud cover” on. Set a sky mask (plate solving) to ignore roads and windows. Events are listed under Gallery & Events.

Cloud Cover

Only this part of the frame is analysed: exclude buildings, trees and the horizon (e.g. bottom 40% if the lower part shows rooftops). The clear-sky reference is learned automatically; reset it after moving or re-aiming the camera.

Daytime objects (birds, insects, aircraft)
Record these kinds
Advanced

Sizes are in pixels at 640 px frame width. Contrast is how far an object must differ from the sky behind it (0–255 levels); empty uses the value of the chosen sensitivity.

By day a small dark or bright dot that moves against the sky is followed across frames and classified from its size, speed and wing-beat flicker. Rain on the dome pauses recording. The frame interval by day (Image Output) sets what can be caught: insects and fast birds need under a second.

Sky Mask

Plate-solve sky mask (outline the open sky)

Press Auto-detect to propose the mask from the current frame (best at night), or click on the frame to outline open sky (green) and lit buildings, trees or poles to ignore (red). Nothing is stored until you press Apply, so you can fix the proposal first. The plate solver only uses stars inside the sky and outside obstructions, on top of its own automatic sky detection.

Align by stars (when the automatic solve is wrong)

Click 4 or more stars you can really see on the open sky (inside the green outline), spread over the frame, brightest first. The solver identifies them from their mutual angles, shows the result, and only stores it when you press Apply.

Integrations

1. Your receiver (primary)

With a local ADS-B receiver (dump1090, readsb or a Flightradar24 feeder: BaseStation port 30003), each aircraft event is matched to the flight whose position, projected with the star-solved camera pointing, lies on the streak. A “meteor” that matches a flight becomes an aircraft. The feed is only read at night while aircraft detection is on.

Off by default. When on, this station sends the aircraft positions your receiver decoded (public broadcast data) to the Zenivo network server (the origin of your remote solver URL; nothing is sent while that is empty), signed with this station's key, every 5 s while your receiver delivers. The server sees this station's IP address and can estimate where your receiver is from what it hears. Data from adsb.fi, adsb.lol or Flightradar24 is never forwarded.

2. Public network (fallback)

Off by default. Used only while your receiver is missing, not connected, or silent for more than 90 s; polling stops as soon as it is back. When on, this station sends its position rounded to 0.5 degree (about 55 km), in this order: to the Zenivo network (only if a remote solver URL is set), then to adsb.fi, and to adsb.lol; the next one is used when one fails or returns no aircraft for 2 minutes. The data is for personal, non-commercial use.

3. Flightradar24 (optional, your own account)

Off by default. When on, this station asks flightradar24.com for the aircraft positions around it; without credentials the public feed is used. Credentials are stored on this station only (token and e-mail in data/station_config.json, the password in memory only, never shown again).

This uses Flightradar24's web endpoints, which are not an official public API. You are responsible for using it within Flightradar24's terms; a subscription token is the supported way for account holders.

Weather balloons (SondeHub)

When on, the station asks api.v2.sondehub.org for the weather balloons within 350 km, about every 20 s while a Live page is open. The position sent is rounded to 0.5° (about 55 km); the exact location never leaves this station.

Weather and forecast

Off by default. When on, the station asks api.open-meteo.com (free, no account) for the weather at its position, rounded to 0.1° (about 11 km); no name, address or picture is sent. Same data at GET /api/weather.

Satellites (orbits)

SatNOGS (db.satnogs.org) is an open, volunteer-run satellite database. It serves one file with every satellite, about 250 KB per download, so the groups below do not apply. Only the request itself is sent, never your position.

Advanced: another orbit source

Leave empty for CelesTrak. The address must be public (https) and return three-line TLE sets for the group named by {group}.

When on, the station asks celestrak.org for orbit data (no position is sent). Satellites are computed locally; a long list slows the live view on a small host, so keep only the groups you want to see.

Community

Shares the station name, an approximate location and, if enabled, a small preview image with other Zenivo stations. Anyone can see it. It is off until you turn it on. The location is rounded as set under Admin → Public location.

Enlarging the preview and the map link need a public URL (up to 1280 px). Turning the link off only removes it from the community map; whoever knows the address can still open the station, as before.

On by default. This station then stores and serves large preview images sent by stations without a public address (re-encoded JPEG, at most 1280 px, up to 100 stations and 25 MB, kept 24 hours). Turning it off deletes everything held and refuses new uploads.

Needs sharing on. Messages pass through hub stations (chat on and a public address): public-room messages are readable by anyone, private messages are end-to-end encrypted, but hubs can see who talks to whom and when. Turning it off stops all chat traffic and deletes what this station held for others; your own history stays.

Seeds

One URL per line. Stations asked first in every round. The built-in ones are listed and can be removed; with an empty list this station only talks to stations it already knows.
